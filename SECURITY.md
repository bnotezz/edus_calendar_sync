# Security Policy

## 🔒 Security Architecture & Best Practices

Цей проєкт взаємодіє з конфіденційними даними: особистими кабінетами шкільного порталу Edus.school, приватними Google Календарями та сервісними обліковими записами. Безпека даних є найвищим пріоритетом.

---

### 1. Ізоляція Секретів та Токенів

* **Файли конфігурації оточення**:
  * `.env.example`: містить безпечний шаблон із фіктивними значеннями. Єдиний файл оточення, який відстежується в системі контролю версій Git.
  * `.env.local` / `.env`: містять локальні змінні середовища та захищені правилом у `.gitignore`. **Категорично заборонено пушити у репозиторій**.
* **GitHub Secrets**:
  * Усі робочі секрети продуктового середовища зберігаються в зашифрованому сховищі GitHub Secrets (`GH_PAT`, `SCHOOL_HOST`, `SCHOOL_LOGIN`, `SCHOOL_PASSWORD`, `GOOGLE_CALENDAR_ID`, `GOOGLE_SERVICE_ACCOUNT_JSON`).
* **Маскування в логах CI**:
  * Робочі воркфлоу GitHub Actions використовують команду `::add-mask::<value>` для будь-яких динамічно згенерованих токенів доступу (JWT) та UUID учнів, що виключає їх випадкове потрапляння у логи виконання.

---

### 2. Принцип Найменших Привілеїв (Least Privilege)

1. **GitHub Personal Access Token (GH_PAT)**:
   * Необхідний виключно для авторотації токенів `SCHOOL_TOKEN`, `SCHOOL_REFRESH_TOKEN` та `SCHOOL_USER_UUID`.
   * **Рекомендація**: Створюйте тільки **Fine-grained Personal Access Token**:
     * Доступ лише до одного репозиторію (`edus_calendar_sync`).
     * Привілеї: тільки `Repository permissions` -> `Secrets: Read & Write`.
     * Термін дії (Expiration): 90 днів із регулярним поновленням.
2. **Google Cloud Service Account**:
   * Надавайте сервісному акаунту доступ **лише до конкретного Google Календаря** дитини (права «Внесення змін до подій» / «Make changes to events»).
   * Не призначайте сервісному акаунту ролей редактора чи власника на рівні Google Cloud проєкту.

---

### 3. Автоматична Ротація Токенів (Smart Auth)

Система реалізує багаторівневу перевірку сесії:
1. Спочатку перевіряється дійсність наявного `SCHOOL_TOKEN` через легкий GET-запит.
2. Якщо токен застарів (HTTP 401/403), виконується запит на оновлення через `SCHOOL_REFRESH_TOKEN`.
3. Лише у випадку недійсності refresh-токена виконується повний логін за логіном і паролем батьківського облікового запису, після чого нові токени автоматично записуються назад у GitHub Secrets через GitHub CLI.

---

### 4. Регулярний Аудит та Перевірка Залежностей

1. **Перевірка застарілих бібліотек**:
   ```bash
   pip list --outdated
   ```
2. **Сканування коду на наявність секретів**:
   Перед кожним комітом запускається навичка перевірки на відсутність приватних ключів (`BEGIN PRIVATE KEY`), Bearer-токенів чи паролів.

---

### 5. Повідомлення про Вразливості (Vulnerability Reporting)

Якщо ви виявили вразливість безпеки в коді, конфігураціях або воркфлоу:
* **Не відкривайте публічні GitHub Issues з описом вразливості.**
* Надішліть приватне повідомлення адміністратору або створіть приватний звіт через **GitHub Security Advisory** у вкладці Security репозиторію.
